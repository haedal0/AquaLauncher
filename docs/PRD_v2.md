## 0. 선행 조건 (개발 착수 전 필수)

개발 코드 한 줄보다 먼저 처리해야 하는 외부 의존성.

1. **Microsoft/Mojang 서드파티 런처 승인 신청**
   - Minecraft 서비스 API(`api.minecraftservices.com`) 접근에는 Azure 앱 등록만으로 부족하며, Mojang의 서드파티 런처 클라이언트 ID 승인이 필요하다.
   - 리드타임이 수 주~수 개월이므로 즉시 신청한다. 신청 시 인증 플로우(§8.3: PKCE + 디바이스 코드 폴백)를 함께 기재한다.
   - **승인 전까지 인증 모듈은 목(mock) 계정으로 개발을 진행하고, 승인 실패 시 프로젝트 전체를 재검토한다 (블로킹 리스크).**
2. **코드 서명 조달**
   - Windows: 코드서명 인증서 (SmartScreen 경고 완화. OV 최소, EV 권장)
   - macOS: Apple Developer Program 가입 + 공증(notarization) 파이프라인
   - 첫 공개 배포 전까지 완료. 미서명 배포는 온보딩 최초 관문에서의 이탈 요인이므로 금지.
3. **Forge/NeoForge 헤드리스 설치 스파이크**
   - Fabric 구현 직후, 로더 추상화 인터페이스 확정 전에 Forge 1개 + NeoForge 1개 버전으로 `--installClient` 방식 검증 프로토타입을 수행한다 (§8.1 함정 목록 확인).
4. **CurseForge API 키 신청 [v2.3 추가]**
   - 모드 브라우저(§8.17)와 curseforge 매니페스트 소스에 필요. 발급에 승인 절차가 있으므로 조기 신청한다.
   - 약관상 제약 확인: 제작자가 배포를 opt-out한 모드는 API가 다운로드 URL을 제공하지 않는다 → §8.17의 폴백 UX가 필수 전제.

## 1. 개요

서버 운영자가 배포하는 모드/리소스팩/설정 구성을 사용자가 수동으로 맞출 필요 없이, 런처가 서버별로 독립된 인스턴스를 자동 생성·동기화해주는 데스크톱 런처. 여러 마인크래프트 서버(모드팩)를 하나의 런처에서 인스턴스 단위로 관리하며, Microsoft 정품 인증, 다중 모드로더(Fabric/Quilt/Forge/NeoForge), Java 자동 관리, 서버별 테마를 지원한다.

**비범위 (이번 버전 제외)**
- 런처 내 마인크래프트 서버 직접 호스팅 (추후 별도 검토)
- 오프라인 계정 모드 (정품 인증 필수. 단, §8.2.6의 "네트워크 단절 시 기존 인스턴스 플레이"와는 별개 개념)
- 텔레메트리 (의도적 미포함)

## 2. 배경 및 문제 정의

- 모드 서버 참여 시 사용자가 정확한 모드 목록/버전/로더/리소스팩/설정을 수동으로 맞춰야 하며, 불일치 시 접속 실패나 크래시가 발생한다.
- 서버 운영자가 배포한 매니페스트만으로 자동 동기화되는 자체 런처가 필요하다.
- 여러 서버를 오가는 사용자를 위해 서버별 독립 환경(모드, 세이브, 설정)을 격리 관리해야 한다.

## 3. 목표 및 성공 지표

**목표**
- 운영자가 매니페스트 하나만 배포하면, 사용자는 URL 입력 또는 딥링크 클릭만으로 인스턴스를 자동 생성하고 플레이할 수 있다.
- 모드/리소스팩/설정 불일치로 인한 접속 실패를 구조적으로 제거한다.
- 멀티 인스턴스 환경을 깔끔하게 제공한다.

**성공 지표 (MVP 출시 후 측정 방법: 텔레메트리 없음 → 커뮤니티 피드백 + 운영자 설문 기반 정성 평가)**
- 신규 사용자가 딥링크 클릭 → 첫 접속까지 개입 없이 완료되는 비율 (운영자 대상 설문)
- "모드 버전 안 맞아요" 류 문의가 파일럿 서버 커뮤니티에서 감소했는가
- 운영자가 매니페스트 업데이트 1회 배포에 걸리는 시간 (목표: CLI로 5분 이내)

## 4. 타겟 사용자

- **일반 플레이어**: 모드 서버에 참여하고 싶지만 모드 설치/버전 관리가 번거로운 사용자
- **서버 운영자**: 모드팩을 쉽게 배포하고 참여자의 환경 불일치 문제를 줄이고 싶은 운영자 (비개발자 포함 — §10의 도구/문서로 지원)

## 7. 데이터 모델

### 7.1 인스턴스와 공유 캐시

인스턴스 = 하나의 독립된 게임 환경. 서버 하나(또는 수동 구성) = 인스턴스 하나. 동일 매니페스트의 중복 인스턴스 생성 허용.

**공유 캐시 정책 [v2 강화]**
- 바닐라 client.jar, 라이브러리, 에셋, JRE는 **내용 주소 저장소(content-addressed store)** 에 저장한다: 파일 경로에 해시를 포함하여, 동시 다운로드가 발생해도 결과가 멱등이 되게 한다.
- 캐시는 **불변(immutable)**: 기존 파일을 덮어쓰지 않고 새 버전은 새 경로로만 추가한다. → Windows 파일 잠금(실행 중 인스턴스가 jar 점유) 문제를 구조적으로 회피.
- 임시 다운로드는 `<이름>.<랜덤>.part`로 수신하여 동시 작업 간 충돌을 방지하고, 해시 검증 후 원자적 rename으로 커밋한다.
- **캐시 GC**: 설정 화면에서 수동 실행. 어떤 인스턴스도 참조하지 않는 캐시 항목을 나열/삭제. 실행 중인 인스턴스가 있으면 GC를 차단한다.
- 모드, 리소스팩, config, 세이브는 인스턴스별 완전 격리.

```json

  "minecraft_version": "1.20.4",

  "manifest_source": "https://yourserver.com/manifest.json",
  "manifest_hash": "sha256:...",
  "manifest_display_version": "12",
  "manifest_pinned": false,
  "auto_update": true,
  "last_synced_at": "2026-06-29T10:00:00Z",
  "install_state": "ready",

  "server": {
    "address": "play.yourserver.com",
    "port": 25565,
    "direct_connect_override": null
  },
  "theme": { "...": "7.3 theme 참고 (로컬 캐시된 사본)" },

  "optional_mods_selection": { "minimap": true, "shaders": false },

  "last_played": "2026-06-29T10:00:00Z",
  "icon": "icon.png"

```

**v2 변경 필드**
- `manifest_hash`: 마지막으로 적용한 매니페스트의 SHA-256. 콘텐츠 변경 감지는 정수 비교가 아닌 **해시 비교**로 수행 (운영자가 버전 숫자 올리는 걸 깜빡하는 휴먼 에러 제거).
- `manifest_display_version`: 사용자 표시용 문자열 (매니페스트의 `display_version` 사본).
- `manifest_pinned`: true면 동기화 체크는 하되 적용하지 않음 (버전 고정).
- `install_state`: `installing | ready | broken`. 설치/동기화 중 크래시 후 재시작 시 복구 판단에 사용.
- `last_synced_at`, `optional_mods_selection` 추가.
- `total_playtime_seconds` 제거 (플레이타임 추적 2차 이동, §12).

```json
    }

  "resourcepack": {
    "filename": "pack.zip",

```

**v2 변경점과 규칙**

- `format_version` (스키마 버전) 과 `display_version` (콘텐츠 표시 버전, 자유 문자열) 을 분리. 런처는 모르는 `format_version`을 만나면 적용을 거부하고 "런처 업데이트 필요"를 안내한다 (§9 E-MF-03). `min_launcher_version`도 동일하게 검사.
- **모드 소스 3종 [v2.3 개정]**: `url`(운영자 직접 호스팅 — 재배포 허용 라이선스인 모드만 사용하도록 §10 문서에 명시) / `modrinth`(원본 참조 — 라이선스 문제 회피 권장 경로) / `curseforge`(`project_id` + `file_id` 참조. 배포 opt-out 모드는 매니페스트 소스로 사용 불가 — §10 CLI `validate`가 검사하여 운영자에게 거부 안내). 어느 소스든 다운로드 후 `sha256` 검증은 동일하게 필수.
- **옵셔널 모드 [MVP 포함, 확정]**: `required: false` 모드는 인스턴스 생성/동기화 시 사용자가 설치 여부를 선택. `optional_group`으로 UI 그룹핑, `default_enabled`로 초기값 제시. 선택 결과는 `instance.json`의 `optional_mods_selection`에 저장되어 이후 동기화에서 유지된다.
- **일반 파일 배포 `files` [신설]**: config, shaderpack, datapack 등 임의 상대경로 파일 배포. `sync_policy` [확정: 운영자가 파일별 지정]:
  - `always`: 해시 불일치 시 항상 서버 버전으로 덮어씀 (서버 필수 설정)
  - `once`: 최초 설치 시 1회만 배포, 이후 사용자 소유 (키바인드, 그래픽 설정 등)
  - `path`는 인스턴스 루트 기준 상대경로만 허용, `..`/절대경로/심볼릭 링크 거부 (경로 탈출 방지).
- `theme.font`: **런처에 번들된 폰트 목록의 키만 허용** (원격 폰트 로딩 금지 — 화이트리스트 정책 우회 차단). 색상은 hex 형식 검증, 이미지 URL은 https만 + 다운로드 후 이미지 포맷 검증 + 용량 상한(5MB).
- 해시는 전 항목 **sha256으로 통일** (v1의 resourcepack sha1 비일관성 제거).
- `recommended_jvm`: 운영자 권장 메모리. 사용자 미설정 시 기본값으로 사용하되 시스템 RAM 상한 규칙(§8.9)이 우선.

### 7.4 로컬 lockfile: manifest.lock.json [v2 신설 — 동기화 엔진의 핵심]

인스턴스 디렉토리에 저장. **마지막으로 적용한 매니페스트가 관리하는 파일의 전체 목록과 출처**를 기록한다. v1의 치명적 공백("과거엔 있었음"을 판단할 데이터 부재)을 해결한다.

```json
{
  "applied_manifest_hash": "sha256:...",
  "applied_at": "2026-06-29T10:00:00Z",
  "managed_files": [
    {
      "path": "mods/sodium-0.5.8.jar",
      "mod_id": "sodium",
      "sha256": "...",
      "origin": "manifest",
      "enabled": true
    },
    {
      "path": "mods/my-custom-mod.jar",
      "mod_id": null,
      "sha256": "...",
      "origin": "user",
      "enabled": true
    }
  ]
}
```

**출처(origin) 규칙**
- `manifest`: 매니페스트에 의해 설치된 파일. 매니페스트에서 사라지면 삭제 대상.
- `user`: 사용자가 직접 추가한 파일. **어떤 경우에도 자동 삭제하지 않는다.**
- 엣지케이스 규칙: 사용자가 직접 넣은 파일과 동일한(해시 일치) 모드가 매니페스트에 추가된 경우, origin은 `user`로 유지한다. → 이후 운영자가 매니페스트에서 제거해도 사용자 파일은 보존된다.
- 매칭 키 우선순위: `mod_id` (매니페스트 유래 파일) → 파일명 → 해시. 동일 `mod_id`의 파일명 변경(버전업)은 "삭제+신규"가 아닌 "갱신"으로 처리한다.

## 8. 기능 명세

### 8.1 다중 모드로더 지원

지원: Vanilla, Fabric, Quilt, Forge, NeoForge (MC 1.13+ 한정)

```rust
trait ModLoader {
    fn id(&self) -> &str;
    fn list_versions(&self, mc_version: &str) -> Result<Vec<LoaderVersion>>;
    fn install(&self, mc_version: &str, loader_version: &str, ctx: &InstallContext) -> Result<LaunchProfile>;
}
```

- Fabric/Quilt: 메타 API 기반. 우선 구현 → 인터페이스 검증.
- **Forge/NeoForge headless 설치 [v2 상세화 — §0-3 스파이크로 선검증]**
  - `java -jar installer.jar --installClient <dir>` 실행. 알려진 함정과 대응:
    - 대상 디렉토리에 `launcher_profiles.json`이 없으면 설치 거부 → 더미 `{"profiles":{}}` 를 사전 생성.
    - 인스톨러가 기대하는 위치에 바닐라 client.jar가 필요 → 공유 캐시에서 하드링크/복사로 스테이징 후 실행하는 "인스톨러 작업 디렉토리" 레이아웃을 정의한다.
    - 설치 프로세서(바이너리 패칭)가 수 분 소요 → UI에 "Forge 설치 중 (최대 수 분 소요)" 단계 표시 + 인스톨러 stdout을 로그로 캡처. 진행률은 불확정(indeterminate) 바로 표시.
    - 산출물 version JSON의 `inheritsFrom` 체인과 플레이스홀더 인자를 §8.15 파이프라인에서 해석.
  - 설치 중 크래시 대비: `install_state=installing` 기록 → 재시작 시 감지하고 설치 디렉토리 정리 후 재시도 안내.

### 8.2 모드/파일 자동 동기화 (동기화 엔진)

#### 8.2.1 트리거 [확정]
- **런처 시작 시**: 모든 인스턴스의 매니페스트를 백그라운드로 fetch하여 해시 비교만 수행. 업데이트가 있으면 인스턴스 카드에 "업데이트 있음 (총 용량)" 배지 표시. **다운로드는 하지 않는다.**
- **플레이 버튼 시**: 해시 재확인 → 변경 있으면 동기화 수행 → 실행.
- 인스턴스 상세 화면에서 수동 "지금 동기화" 버튼 제공.
- `manifest_pinned=true`면 배지 표시만 하고 적용하지 않음.

#### 8.2.2 대용량 업데이트 확인 [v2 신설]
- diff 총 다운로드 용량이 **200MB 이상**이면 다운로드 시작 전 diff 요약(추가 N개 / 갱신 M개 / 삭제 K개, 총 용량)과 changelog를 보여주는 확인 다이얼로그를 표시한다. 미만이면 자동 진행.
- 다운로드 중 일시정지/취소 가능. 취소 시 기존 상태 유지(§8.2.4 스테이징 덕분에 안전).

#### 8.2.3 Diff 로직

| 매니페스트 | 로컬(lockfile 기준) | 액션 |
|---|---|---|
| 있음 | 없음 | Download |
| 있음 | 있음, 해시 일치 | Keep |
| 있음 | 있음, 해시 불일치 | Download(갱신) |
| 있음 | Disabled 상태 | **갱신하되 disabled 상태 유지** (파일은 최신으로, 사용자 의도 존중) [v2 규칙 확정] |
| 있음(optional, 사용자 미선택) | 없음 | Skip |
| 없음 | origin=user | 보존, UI에 "사용자 추가" 구분 표시 |
| 없음 | origin=manifest | Remove |

- lockfile에 없는 미지의 파일이 mods/에 존재하면 origin=user로 등록 (사용자가 런처 밖에서 직접 넣은 경우).

#### 8.2.4 원자성: 스테이징 → 커밋 [v2 신설]
1. 모든 다운로드를 인스턴스 내 `.staging/` 디렉토리에 수신 + 해시 검증 완료까지 기존 파일은 건드리지 않는다.
2. 전체 다운로드 성공 시에만 커밋 단계 진입: 삭제 → 이동(rename)을 일괄 수행하고 lockfile과 `manifest_hash`를 갱신.
3. 어느 단계든 실패하면 `.staging/` 폐기, 인스턴스는 이전 정합 상태 그대로. "신구 혼합 상태"는 발생하지 않는다.
4. 커밋 도중 크래시 대비: 커밋 시작 전 저널 기록 → 재시작 시 저널 발견하면 커밋 재개 또는 롤백.

#### 8.2.5 다운로드
- `.part` + 랜덤 접미사 임시 파일, SHA-256 검증 후 rename.
- HTTP Range 이어받기, 미지원 서버는 처음부터 재다운로드 폴백.
- 동시 다운로드 수 기본 4 (전역 설정에서 조정), 파일 단위 재시도 3회.

#### 8.2.6 오프라인/장애 시 플레이 [v2 신설]
- 매니페스트 fetch 실패(네트워크 단절, 서버 다운) 시: 마지막 정합 상태로 **플레이는 허용**하되 "동기화 확인 실패 — 마지막 동기화 {시각}" 경고 배지를 표시한다. (MS 토큰 갱신이 불가능한 완전 오프라인이면 인증 단계에서 별도 안내, §9)
- 이 정책 덕에 운영자 서버 다운이 사용자 게임 불가로 번지지 않는다.

#### 8.2.7 검증/복구 [v2 신설]
- 인스턴스 메뉴에 "파일 검증" 제공: lockfile의 managed_files 전체 해시를 재검사하고 불일치/누락 파일만 재다운로드. (v1의 "해시 같으면 영원히 스킵 → 손상 복구 불가" 문제 해결)

#### 8.2.8 모드 개별 토글
- 비활성화는 확장자 변경(`.jar` ↔ `.jar.disabled`), lockfile의 `enabled`에 반영.
- **required 모드 토글 시 [확정]**: 차단하지 않되 "이 모드는 서버 필수입니다. 끄면 접속 실패/크래시가 발생할 수 있습니다" 경고 다이얼로그 후 허용.
- 관리 모드가 하나라도 비활성/수정 상태면 인스턴스 카드에 **"수정됨" 배지** 표시 + 실행 직전 "비활성화된 필수 모드 N개" 리마인더.
- **"매니페스트 상태로 초기화" 원클릭 버튼**: 모든 관리 파일을 매니페스트 정의 상태로 복원 (사용자 추가 파일은 건드리지 않음).

### 8.3 인증 및 계정 관리 [v2 개정]

- **플로우 [확정]**: Authorization Code + PKCE (시스템 브라우저 + `http://localhost:<random-port>` 리다이렉트) 기본. 브라우저 실행 실패/헤드리스 환경에서는 디바이스 코드 플로우 폴백.
- 인증 체인: MSA → Xbox Live → XSTS → Minecraft 토큰. 각 단계 실패를 §9의 에러 코드로 분류.
- **XSTS 에러 처리 [v2 필수]**:
  - Xbox 프로필 없음 → 프로필 생성 페이지로 안내
  - 자녀 계정 → 가족 등록 필요 안내
  - **한국 계정 성인 인증 미완료 → Xbox 성인 인증 페이지 링크와 절차 안내 (한국 사용자 최다 이탈 지점, 전용 안내 화면 필수)**
- **Game Pass 사용자 [v2 필수]**: entitlement 엔드포인트에 게임이 잡히지 않으므로, 소유권 판정은 **프로필 조회(profile endpoint) 성공 여부**를 기준으로 한다. entitlement만 보고 차단하지 않는다.
- 멀티 계정 등록/전환, 인스턴스별 `last_account_id` 기억.
- `refresh_token`은 OS 자격증명 저장소(Windows Credential Manager / macOS Keychain)에 저장.
- 로그인은 온보딩 첫 화면에서 강제하지 않고, **플레이 직전 필요 시점에 요구**한다 (§C1 반영).

### 8.4 Java 자동 관리
- Mojang 버전 매니페스트의 `javaVersion.majorVersion` 사용.
- 없으면 Adoptium API에서 플랫폼(아키텍처 포함: macOS는 aarch64/x64 구분) 맞는 JRE 자동 다운로드 → 공유 캐시에 저장.
- `java_path_override`로 사용자 지정 가능. 지정 시 메이저 버전 불일치면 경고.

### 8.5 서버별 테마
- 화이트리스트 필드만: 색상(hex 검증), 이미지(https + 포맷 검증 + 5MB 상한), 번들 폰트 키. 임의 CSS/HTML 금지.
- 1차 범위: 인스턴스 카드 + 인스턴스 상세 화면 스타일링. CSS 변수 매핑.
- **가독성 보정 [v2 신설]**: `primary_color` 위 텍스트는 명도 대비(WCAG 4.5:1) 기준으로 흰/검 자동 선택. 운영자 실수로 UI가 안 읽히는 상황 방지.
- 테마 리소스는 다운로드 후 로컬 캐시 사본을 사용 (매 실행마다 원격 로딩 금지).

### 8.6 서버 접속 연동 [v2 개정 — 버전 분기 필수]
- 동기화 시 `servers.dat`(NBT)에 서버 자동 등록.
  - **쓰기 타이밍 규칙**: 게임이 종료 시 servers.dat를 통째로 다시 쓰므로, 런처는 **해당 인스턴스의 게임이 실행 중이 아닐 때 + 실행 직전에만** 수정한다.
  - 알 수 없는 NBT 필드는 보존(round-trip).
- **자동 접속 인자 [v2 수정]**:
  - MC **1.20 이상**: `--quickPlayMultiplayer "host:port"` (v1의 `--server`/`--port`는 1.20에서 제거되어 동작 안 함)
  - MC 1.13 ~ 1.19.x: `--server <host> --port <port>`
- 인스턴스 설정에서 on/off, 매니페스트 `direct_connect_default`는 초기값만 제공.

### 8.7 딥링크 설치 [v2 개정]
- `aqualauncher://add?manifest=<url-encoded-https-url>` 커스텀 스킴 등록.
- 싱글 인스턴스 보장: 실행 중이면 기존 창에 전달.
- **확인 모달에 표시할 정보 [v2 강화]**: 서버 이름 + **매니페스트 출처 도메인**(스푸핑 방어) + 모드 개수 + 총 다운로드 용량. 사용자가 승인해야 생성 진행.
- **미설치 사용자 대응 [v2 신설]**: 운영자에게 `aqualauncher://` 원시 링크 대신 **https 랜딩 페이지 링크** 배포를 표준으로 안내한다. 랜딩 페이지(정적 HTML 템플릿을 §10 CLI가 생성)는 런처 실행을 시도하고, 일정 시간 내 포커스 전환이 없으면 런처 다운로드 안내를 표시한다.
- 이미 동일 `manifest_source`의 인스턴스가 존재하면: "기존 인스턴스 열기 / 새로 하나 더 만들기" 선택지 제공.
- 매니페스트 URL은 https만 허용, 스키마 검증 통과 후에만 모달 표시.

### 8.8 인스턴스 생애주기 (MVP 범위)
- **삭제**: 세이브를 백업 폴더로 이동 후 삭제 (기본값, 옵션으로 끄기 가능). 백업 폴더 위치를 완료 토스트에 표시.
- **가져오기**: 매니페스트 URL 입력 / 매니페스트 .json 파일. (백업 zip 가져오기는 내보내기와 함께 2차)
- **수동 인스턴스 (직접 만들기) [v2.2 상세화]**: "인스턴스 추가" 화면에서 매니페스트 URL 입력과 동급의 경로(탭)로 제공한다.
  - 입력 항목: 이름 / MC 버전(Mojang 버전 매니페스트의 릴리스 목록, 스냅샷은 토글로 노출) / 로더 종류·버전 / 아이콘 색상(선택, 기본 자동 배정)
  - 생성 즉시 빈 인스턴스로 플레이 가능. 모드는 사용자가 모드 탭 또는 mods 폴더에서 직접 관리하며 lockfile의 모든 항목이 origin=user.
  - 매니페스트 동기화 관련 UI(업데이트 배지, changelog, 초기화 버튼)는 수동 인스턴스에서 표시하지 않는다.
- 복제/내보내기는 2차로 이동 [확정] — 단, zip 관련 코드 작성 시 Zip Slip 방지 경로 검증 원칙은 §11에 유지.

### 8.9 JVM 설정
- 인스턴스별 `-Xms`/`-Xmx` + 추가 인자.
- 기본값 우선순위: 사용자 설정 > 매니페스트 `recommended_jvm` > 자동 추천(시스템 RAM 절반, 상한 8GB, 하한 2GB).
- `jvm_args_override`로 전체 무시하고 직접 입력 가능.

### 8.10 진행 상황 표시
- 단계(Java → 라이브러리 → 에셋 → 로더 → 모드 → 파일 → 리소스팩)를 Tauri 이벤트로 푸시 (100ms 스로틀).
- 통합 진행률 + 단계 텍스트 + 현재 파일명 + **예상 남은 용량**.
- 첫 설치 시 "최초 설치는 {예상 용량} 다운로드가 필요합니다" 사전 안내 (§C1 반영).
- 실패 시 실패 파일 목록과 함께 부분 재시도 버튼.

### 8.11 런처 자동 업데이트
- Tauri 업데이터 + 서명 검증. 시작 시 자동 체크 + 수동 체크.
- `format_version`/`min_launcher_version` 미충족 매니페스트를 만난 경우 업데이트 유도 화면과 연결.
- 하위 호환 깨지는 변경 시 "필수 업데이트" 플래그로 건너뛰기 차단.

### 8.12 진단: 로그 및 크래시 리포트
- 외부 전송 없음, 로컬 보관. `tracing` 일자별 로테이션, 보관 기간 설정.
- 런처 크래시: panic hook → 로컬 JSON.
- 게임 크래시: 종료 코드 확인 → crash-reports를 인앱 뷰어에 표시. **크래시 루프 방지**: 동일 인스턴스가 5분 내 3회 비정상 종료하면 자동 재실행 제안을 중단하고 진단 화면으로 유도.
- 로그 내 토큰/이메일 등 민감 정보 마스킹 필수. 폴더 열기 / 클립보드 복사 제공.

### 8.13 다국어 지원 (i18n)
- 문자열 하드코딩 금지, 리소스 파일 분리. 1차 언어: 한국어, 영어.

### 8.14 UI 레이아웃 및 인스턴스 목록 관리 [v2.1 개정 — 레이아웃 확정]

**전체 레이아웃: 좌측 사이드바 + 우측 상세 (바닐라 런처/Discord 스타일)**
- **좌측 사이드바**: 인스턴스 목록. 항목 = 서버 로고 아이콘 + 이름(말줄임 + 툴팁) + 상태 배지("업데이트 있음", "수정됨", "동기화 확인 실패"). 하단에 "인스턴스 추가" 버튼 고정.
- **우측 메인 영역**: 선택된 인스턴스의 테마(§8.5)가 적용된 상세 화면 — 배경 이미지, 로고, 서버 설명, changelog, 모드 목록 탭, 설정 탭. **플레이 버튼은 항상 동일 위치에 고정** (우측 하단).
- 사이드바 항목의 아이콘/포인트 컬러에 인스턴스 테마 적용, 전체 테마 스타일링은 메인 영역에서 표현.
- 바닐라 런처와 달리 목록이 길어질 수 있으므로: 사이드바 내 스크롤 + 상단 검색 입력, 기본 정렬 최근 플레이 순(이름순 전환 가능).
- 인스턴스 미선택/0개 상태: 온보딩 안내(딥링크/URL로 추가하는 방법)를 메인 영역에 표시.
- 그룹/태그(사이드바 섹션 접기)는 2차.
- **런처 외형 테마 (라이트/다크) [v2.2 신설]**: 기본값은 OS 설정 따름, 전역 설정에서 수동 전환. 서버 테마(§8.5)의 색상은 라이트/다크 양쪽 모드에서 배경 혼합값을 모드별로 파생하며, 두 모드 모두 대비 규칙(4.5:1)을 충족해야 한다.
- 인스턴스별 디스크 사용량 표시 (상세 화면 설정 탭).

### 8.15 게임 실행 파이프라인 [v2 신설 — v1 누락 보완]

런처의 최대 구현 덩어리. 별도 기술 설계 문서(TD-01)로 상세화하되, PRD 수준 요구사항은 다음과 같다.

1. **version JSON 해석**: Mojang 버전 JSON + 로더 version JSON의 `inheritsFrom` 체인 병합. `rules` 배열(OS/아키텍처 조건부 라이브러리·인자) 평가.
2. **클래스패스 조립**: 병합된 라이브러리 목록 → 공유 캐시 경로로 해석. 로더 라이브러리가 바닐라와 중복될 때 로더 측 우선.
3. **natives**: 플랫폼별 native 라이브러리를 인스턴스별 임시 디렉토리에 추출.
4. **에셋**: asset index 해석, 공유 캐시의 objects 참조.
5. **인자 치환**: `${auth_access_token}`, `${game_directory}` 등 플레이스홀더 치환. **토큰이 로그에 남지 않도록 마스킹.**
6. **프로세스 관리**: 자식 프로세스 spawn, stdout/stderr 캡처(인앱 로그 뷰어), 종료 코드 감시.
7. game_directory는 인스턴스 디렉토리로 격리.

### 8.16 사전 검증(Pre-flight) 범위
- 클라이언트 검증: 디스크 공간(diff 용량 + 20% 여유), 매니페스트 구조 유효성(중복 mod id, 잘못된 경로, 미지원 버전).
- 모드 간 실제 호환성 충돌은 운영자 책임 영역 (§10 CLI의 validate가 구조 검증 보조).

### 8.17 모드 브라우저 — Modrinth / CurseForge 검색·설치 [v2.3 신설]

런처 안에서 모드를 검색해 인스턴스에 바로 설치하는 기능. 수동 인스턴스의 핵심 워크플로우이자, 매니페스트 인스턴스에 개인 모드를 추가하는 경로.

- **대상**: 모든 인스턴스. 설치된 모드는 lockfile에 **origin=user**로 기록되어 매니페스트 동기화의 삭제 대상에서 제외된다 (§7.4 규칙 그대로).
- **호환성 필터**: 검색 결과는 현재 인스턴스의 MC 버전 + 로더로 자동 필터. 기본으로 최신 호환 버전을 설치하되, 버전 드롭다운으로 수동 선택 가능.
- **의존성 처리**: 플랫폼 API가 제공하는 required dependency를 자동 감지하여 함께 설치할 것을 제안(기본 체크됨). optional dependency는 표시만.
- **다운로드/검증**: §8.2.5와 동일 파이프라인(임시 파일 + 해시 검증 + 원자적 rename). API가 제공하는 해시를 사용.
- **CurseForge 특수 처리**:
  - API 키 필요 (§0-4). 키는 앱에 내장하되 빌드 시 주입, 로그 마스킹 대상.
  - **배포 opt-out 모드**: API가 파일 URL을 제공하지 않음 → 설치 버튼 대신 "브라우저에서 받기" 링크(공식 페이지) + "다운로드한 파일 직접 지정" 폴백 제공 (§9 E-MB-01). 검색 결과에서 숨기지 않고 제한 사실을 표시한다 (숨기면 사용자가 "검색이 안 된다"고 오인).
- **API 예절**: 각 플랫폼의 rate limit 준수, 식별 가능한 User-Agent 전송, 검색 디바운스(300ms).
- **범위 제한 (2차로)**: 브라우저로 설치한 사용자 모드의 업데이트 확인/일괄 업데이트, 모드팩(컬렉션) 검색, 스크린샷·설명 상세 페이지.

## 10. 서버 운영자 도구 및 워크플로우 [v2 신설]

### 10.1 매니페스트 생성 CLI (MVP 포함)

```
aqua-cli init                # 대화형으로 서버 정보/테마 입력 → manifest.json 골격 생성
aqua-cli scan ./instance-dir # mods/, config/ 등을 스캔해 해시/용량 자동 계산, mods/files 섹션 갱신
aqua-cli add-modrinth <slug> # Modrinth API에서 project/version id, 해시 자동 채움
aqua-cli validate            # 스키마 검증 + 모든 URL HEAD 체크 + 해시 재확인
aqua-cli diff old.json new.json  # 사용자에게 배포될 변경 요약 미리보기
aqua-cli landing             # 딥링크 랜딩 페이지 정적 HTML 생성 (§8.7)
```

- 운영자는 해시/용량을 손으로 계산할 일이 없어야 한다.
- 업데이트 배포 흐름: 로컬에서 모드 교체 → `scan` → `validate` → 파일 업로드 → manifest.json 교체. (해시 비교 방식이므로 버전 숫자 올리는 것을 잊어도 배포된다. `display_version`은 표시용.)

### 10.2 호스팅 요구사항 문서 (배포물에 포함)
- HTTPS 필수, Range 요청 지원 권장.
- 정적 호스팅이면 충분함을 명시 + GitHub Pages / 오브젝트 스토리지 튜토리얼 제공.
- **라이선스 가이드**: 재배포 금지 모드는 `source: modrinth`를 사용할 것. 직접 호스팅(`source: url`)은 재배포 허용 라이선스 확인 후 사용.
- 대역폭 추정 가이드 (동시 접속자 × 평균 diff 용량).
